# CACSMS Sports — System Audit & Remediation (2026-11-17)

Scope of this pass: runtime configuration, the BetExplorer acquisition path, market freshness (`NO_FRESH_MARKET`),
model governance, the 12-stage engine's evidence gates, browser isolation, and API route integrity.
Every finding below has evidence from this environment (Windows 11, backend venv Python 3.14, PostgreSQL at alembic
head `0015`, Playwright 1.64.1 + Chromium 156). PAPER mode was enforced throughout; no wagers, codes or results were
created. The live database was only read (`SET TRANSACTION READ ONLY`); PostgreSQL tests ran on a disposable database.

## 1. BetExplorer root cause — **not a defect: blocked by the operator's terms (correct behaviour)**

| Check (run from the backend venv) | Result |
|---|---|
| DNS `www.betexplorer.com` | `188.92.44.58` |
| TLS | TLSv1.3, `*.betexplorer.com`, valid to 2027-01-22 |
| `GET /robots.txt`, `GET /terms-of-service.php` | 200 / 200, no redirects, no bot challenge |
| Terms text (re-read 2026-11-17) | still contains: *"not permitted to use our content … by embedding, aggregating, scraping or recreating it without our express consent"*, *"no extraction (copying) … of the Database Content"*, *"must not burden our server … with automated requests"* |
| Registry row | `BetExplorer PROHIBITED enabled=False`, 0 observations |
| Enforcement | browser `vision/security.validate_destination` and feed `acquisition/jobs.validate_feed_url` both refuse the host (verified live: direct capture raises `PermissionError`) |

Conclusion: the network and browser stack can reach BetExplorer; data is absent **only** because
`acquisition/source_policy.py` correctly refuses automated collection. No navigation or extraction of sports pages was
performed, because that would itself be the prohibited activity. The same-hostname request restriction is irrelevant to
BetExplorer (refused before any request).

**Status: BLOCKED (legal).** Corrective action: obtain express written consent / a data licence from Livesport s.r.o.
and record it as `SPORTS_SOURCE_CONSENT=betexplorer.com=<reference>`. An extraction adapter should be built only after that.

Authorized alternative already operating with real data: Football-Data.co.uk (10,307 observations) and OpenLigaDB
(2,871), 10,461 fixtures (225 upcoming), 2,610 result-evidence records, 238,664 archived prices.

## 2. `NO_FRESH_MARKET` root cause — **BLOCKED (external data), gates correct**

- All 9 open runs wait at **Evaluate** with `NO_FRESH_MARKET`; Reconcile waits for kickoff (correct).
- All 238,664 stored prices are historical *closing* prices from season CSVs (latest 2026-11-08). **0 prices exist for
  any upcoming fixture.**
- The only permitted pre-match price feed, `football-data.co.uk/fixtures.csv`, was fetched now: Last-Modified
  2026-11-13 14:16 UTC (81 h old), 51 rows, **no D1 (Bundesliga) rows** (international break; next fixture 2026-11-20).
  Only Bundesliga fixtures are priced because they alone have two independent sources for identity/results.
- Evaluate requires quotes ≤ 15 min old (`pipeline/operations.py:QUOTE_MAX_AGE`); prices are honestly stamped with the
  file's Last-Modified time. A file updated every few days will rarely satisfy a 15-minute window.

Corrective action (owner decision, deliberately not changed): either license a near-real-time odds API (credentials
required) or adopt a source-specific, explicitly labelled freshness policy for PAPER evaluation. Loosening the gate
silently would let selections qualify on stale prices.
